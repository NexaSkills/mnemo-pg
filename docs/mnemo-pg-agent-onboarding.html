1. What mnemo-pg is

mnemo-pg replaces the SQLite storage layer under the mnemosyne Hermes memory provider with native PostgreSQL on the existing lcm-pg cluster (PG 18.6, pgvector, tsvector/GIN FTS). The hooks and 57 mnemosyne_* tools Hermes sees are unchanged — only the storage path swaps. A profile never touches SQLite: the provider class comes from the repo loader and sqlite3.connect to store paths is bound to the PG backend.

  • One schema per Hermes agent profile: mnemosyne_default, mnemosyne_alpha, …
  • Native shapes: bigint identity rowids, HNSW vector(384) cosine KNN, tsvector+GIN full-text with mnemo_normalize_fts, FK ON DELETE CASCADE vec companions.
  • No shims at deploy time: schema is provisioned from native_ddl.py; the legacy runtime shim exists only for the SQLite→PG migration window and is retired with the DBs.

2. Deploy a host (template today, fleet later)

Authoring happens only on beez (~/workspace/mnemo-pg/repo → push to main). Hosts run exactly one script:

bash ~/.hermes/plugins/mnemo-pg/mnemo_update.sh --ref main

What it does, in order (mirrors lcm-pg pipeline v2):

  1. Fetch the pinned GitHub ref (fresh clone into the plugin location on clean hosts).
  2. Materialize code into ~/.hermes/plugins/mnemo-pg/ and link ~/.hermes/plugins/mnemosyne + every profiles/<p>/plugins/mnemosyne directory to the repo's plugin/ loader (content replaced, path kept — see the gotcha in §4).
  3. Params: pins ops/env_spec.txt (MNEMO_BACKEND=postgres, embeddings, polyphonic flag) into root + profile .env; retires any *mnemo-poly*.conf systemd overrides (root .env is the single source).
  4. DB migrations BEFORE restarts: provision schemas, migrate that host's own SQLite data (parity-gated), stamp per (schema, ref) so reruns are no-ops.
  5. Discover & restart all surfaces (systemctl --user units matching hermes-*).
  6. check_all.py prints the full matrix — that's the gate.

3. Create a new agent profile (already migrated)

The new-profile tooling on this host is mnemo-pg-aware (see scripts/new_profile.sh in the repo). It:

  1. Creates ~/.hermes/profiles/<name>/ (config from default, plugin dirs).
  2. Provisions mnemosyne_<name> in PG (scripts/provision_schema.py, idempotent).
  3. Links profiles/<name>/plugins/mnemosyne content to the mnemo-pg loader and pins ops/env_spec.txt keys into profiles/<name>/.env.
  4. Runs scripts/check_shape.py mnemosyne_<name> + scripts/check_all.py so the profile is correct from its first turn.
On an already-deployed host, creating a profile is also self-healing: the plugin loader's _ensure_schema provisions any missing schema at first use — but the scripted route is the verified one.

4. The one gotcha: pip vs the plugin dir

Symptom: an agent answers about old context, and its SQLite mnemosyne.db mtime keeps moving — it's running the pip-installed provider (site-packages/mnemosyne_hermes/), not mnemo-pg.

Cause: Hermes discovers plugins from both the plugin directory (loads its register() from disk) and the pip-installed package re-exported by that catalog shim. The install flow replaces the plugins/mnemosyne/ directory contents in place (path must stay plugins/mnemosyne). A symlink named mnemosyne is not accepted as that directory by the plugin machinery on some hosts.

Fix: mnemo_update.sh materializes the loader as the directory contents; check_all.py verifies the running provider's __file__ resolves under ~/.hermes/plugins/mnemo-pg/, not site-packages.

python3 scripts/check_shape.py mnemosyne_<p> # native shape: identity rowids, GIN, HNSW, FKs, fts fn

Green = provider from the repo dir, every profile schema provisioned + shaped, vector
  coverage 100%, recall probes return relevant hits with polyphonic scoring, and
  retire_check.py is clean (no live SQLite).

7. SQLite retirement (done as part of deploy)

  • scripts/retire_sqlite.py archives every live mnemosyne*.db(-wal|-shm) to ~/.hermes/backups/mnemosyne-sqlite-retired-<ts>/ and deletes originals (verification before delete; --dry-run supported).
  • scripts/retire_check.py runs on the mnemo-sqlite-tripwire systemd-user timer every 10 min and alarms if a live SQLite DB reappears (i.e. something is still writing the old path).
  • Backups stay inside ~/.hermes; nothing outside ~/.hermes is touched.
